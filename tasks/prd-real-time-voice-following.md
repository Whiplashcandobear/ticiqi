# PRD：实时语音跟随与固定 WPM 双模式

## 文档状态

- 状态：方案已确认，等待实现前评审
- 日期：2026-09-30
- 适用项目：英语演讲手机提词器 Android APK
- 视觉参考：沿用现有深色/浅色提词界面，不新增复杂视觉风格

## 1. 产品概述

当前 APK 使用固定 WPM 计算每句话的展示时长。当演讲者临时停顿、加速或放慢时，字幕可能提前或滞后。本功能增加两种可以自由切换的提词模式：

1. **固定 WPM**：完全保留现在的行为，按设定的 WPM 自动播放，支持现有暂停、继续、拖动、从头、横竖屏、字母级高亮和悬浮窗。
2. **实时语音跟随**：使用手机麦克风进行英语语音识别，根据识别到的台本位置推进当前句和高亮；识别暂时不可用时，约 2 秒后自动回退到固定 WPM。

实时语音跟随优先使用设备端识别，不保存录音文件。它的目标是实现稳定的**句子级同步**，不承诺逐字识别始终准确。

## 2. 已确认的产品决策

| 项目 | 决策 |
|---|---|
| 提词模式 | 用户可选择“固定 WPM”或“实时语音跟随” |
| 固定 WPM | 完全保留现有设置和播放逻辑 |
| 语音同步粒度 | 句子级同步；当前句继续支持字母级视觉高亮 |
| 识别方式 | 离线优先，优先使用设备端英语识别 |
| 识别失败 | 无有效识别约 2 秒后回退固定 WPM |
| 音频文件 | 只使用实时音频流，不保存、不上传、不保留回听文件 |
| 识别失败后的速度 | 使用用户设置的 WPM；仍可用 `−5 / +5 WPM` 调整 |
| 麦克风权限 | 只有选择实时语音跟随时申请；固定 WPM 不申请 |
| 主使用场景 | 手机 A 录制视频，手机 B 显示台本；也支持 Android 悬浮窗单机使用 |

## 3. 目标与成功标准

### 3.1 产品目标

- 让用户可以在固定速度和实时跟随之间快速选择，不被单一算法限制。
- 在安静环境、正常英语演讲状态下，让当前高亮句跟随用户实际朗读位置。
- 在识别不可用、无网络、环境噪声或权限拒绝时，仍然可以使用当前固定 WPM 功能。
- 不保存用户演讲音频，不新增账号、服务器和云端数据。

### 3.2 成功标准

- 固定 WPM 模式的行为与当前 APK 一致，已有功能不回归。
- 设备支持离线识别且环境安静时，至少 90% 的句子切换能在实际读到句末约 1.5 秒内完成。
- 连续约 2 秒没有有效识别结果时，字幕自动切换到固定 WPM，不出现永久停住。
- 识别服务报错、权限被拒绝或设备不支持离线识别时，用户可以继续使用固定 WPM。
- 实时模式不保存音频文件，不向应用服务器上传语音内容。
- 用户手动拖动全文时，自动跟随不会强行把视图拉回；用户可以点击“恢复跟随”。

## 4. 用户故事

### US-001：选择提词模式

**描述：** 作为演讲者，我希望选择固定 WPM 或实时语音跟随，以适应不同录制环境。

**验收标准：**

- [ ] 播放设置显示“固定 WPM”和“实时语音跟随”两个选项。
- [ ] 默认仍为固定 WPM，升级后不会改变已有用户的播放方式。
- [ ] 选择固定 WPM 时，不申请麦克风权限。
- [ ] 选择实时语音跟随时，在开始播放前显示麦克风权限和识别能力状态。

### US-002：实时句子跟随

**描述：** 作为演讲者，我希望字幕根据我读到的句子推进，而不是只按预设速度滚动。

**验收标准：**

- [ ] 识别到当前台本句子的连续内容后，当前句高亮跟随到正确句子。
- [ ] 字幕不会因为单次识别结果中的一个错词就跳过多个句子。
- [ ] 当前句的字符高亮可以根据已匹配的词语逐步推进；无法稳定匹配时保持当前视觉状态。
- [ ] 识别结果只允许播放位置向前推进，除非用户手动拖动或点击从头。

### US-003：识别失败自动回退

**描述：** 作为演讲者，我希望识别暂时失败时字幕仍然继续，不让录制流程被卡住。

**验收标准：**

- [ ] 连续约 2 秒没有有效识别结果后，状态显示“固定速度跟随”。
- [ ] 回退速度使用当前 WPM，可通过 `−5 / +5 WPM` 调整。
- [ ] 语音识别恢复后，系统只在匹配结果稳定时重新接管，不突然跳过多个句子。
- [ ] 识别服务报错时提供“重试语音跟随”和“继续固定 WPM”两个结果。

### US-004：悬浮窗实时跟随

**描述：** 作为只有一台手机的用户，我希望在摄像头应用上方使用实时语音跟随的悬浮台本。

**验收标准：**

- [ ] 悬浮窗模式显示识别状态、当前句和当前 WPM。
- [ ] 悬浮窗使用相同的句子匹配和回退规则。
- [ ] 关闭悬浮窗或退出播放后停止语音识别并释放麦克风。
- [ ] 悬浮窗仍然支持拖拽、全文滚动、进度拖动、暂停、字体和背景设置。

### US-005：固定 WPM 兼容性

**描述：** 作为不希望使用麦克风的用户，我希望继续使用现有的固定速度提词。

**验收标准：**

- [ ] 固定 WPM 模式不启动语音识别。
- [ ] 倒计时、当前句计时、进度条、预计剩余、拖动位置和从头开始逻辑保持不变。
- [ ] 横屏紧凑控制区和竖屏布局保持现有行为。
- [ ] 现有语速校准和 `−5 / +5 WPM` 调节仍然可用，并作为固定 WPM 或回退 WPM 的来源。

## 5. 功能需求

### FR-1：模式设置

系统必须在播放设置中提供：

- `固定 WPM`
- `实时语音跟随`

模式保存到本机设置中。默认值为固定 WPM，以保证现有用户升级后无行为变化。

### FR-2：语音权限与能力检查

进入实时语音跟随前，系统必须按顺序检查：

1. `RECORD_AUDIO` 权限是否已授予。
2. 设备是否存在可用英语语音识别服务。
3. 在 Android 支持的情况下，是否存在可用的设备端识别能力。

检查失败时不得阻止用户选择固定 WPM。界面必须明确说明失败原因，并提供“继续固定 WPM”。

### FR-3：实时识别输入

- 识别语言固定为英语，具体语言标签由实现层使用系统可用的英语 locale。
- 只消费 partial/final recognition result，不保存音频文件。
- 识别器生命周期与播放生命周期绑定：播放开始时启动，退出、停止、暂停到用户关闭语音跟随时释放。
- 识别监听必须能够报告：识别中、识别暂时无结果、识别不可用、识别错误、识别已停止。

### FR-4：台本文本归一化

为避免识别文本和台本格式不同导致匹配失败，匹配层必须统一处理：

- 转小写。
- 将弯引号和直引号视为同一类字符。
- 去除句号、逗号、问号、感叹号等非必要标点。
- 连续空格折叠为一个空格。
- 保留英文单词顺序。
- 与现有 `SpeechTextParser` 的句子边界保持一致。

### FR-5：句子匹配策略

匹配器以当前句为优先，并只在当前句及后续有限窗口中搜索，避免一次识别误差导致跳到全文后部。

建议匹配流程：

1. 把台本拆成句子和单词 token，并为每个 token 保存原始显示位置。
2. 接收识别 partial result 后，提取最近一段有效英文词。
3. 先做连续前缀匹配，再做允许少量错词的模糊匹配。
4. 当当前句匹配覆盖率达到阈值，或识别到句末词并连续两次结果一致时，提交当前句完成。
5. 一次结果最多推进到下一个句子，不允许跨过多个句子。
6. 识别结果不稳定时，只更新候选匹配进度，不改变已确认的句子索引。

初版只保证句子级跟随；不以一次 partial result 直接驱动逐字跳转，避免识别修正造成文字闪烁。

### FR-6：混合状态机

实时语音跟随使用以下状态：

```text
VOICE_READY
    ↓ 开始播放
VOICE_LISTENING
    ├─ 有稳定匹配 → 更新当前句/字符进度
    ├─ 约 2 秒无有效结果 → FALLBACK_WPM
    └─ 权限/服务错误 → FIXED_WPM_ERROR

FALLBACK_WPM
    ├─ 识别恢复且匹配稳定 → VOICE_LISTENING
    ├─ 用户点击暂停 → PAUSED
    └─ 用户选择固定模式 → FIXED_WPM
```

回退时不重置句子索引和当前进度。语音恢复时，识别结果必须先与当前句或下一句稳定匹配，才允许重新接管。

### FR-7：手动操作优先级

- 用户拖动进度条后，自动跟随暂时停止拉动视图。
- 用户拖动全文时，只改变视口，不改变已确认的识别句索引。
- 界面显示“恢复跟随”按钮，点击后回到当前识别句。
- 点击暂停时同时暂停 WPM 回退计时；是否继续保持识别监听由实现选择，但不能在暂停期间推进台本。
- “从头”会重置句子索引、匹配器和回退计时，并按当前模式重新开始。

## 6. 界面设计

### 6.1 播放设置页

在现有“滚动速度”附近新增“提词模式”：

```text
提词模式
[固定 WPM] [实时语音跟随]
```

固定 WPM 选中时显示当前 WPM 预设、校准和说明。实时语音跟随选中时显示：

- “需要麦克风权限，仅用于实时识别”
- “音频不保存、不上传”
- “识别失败约 2 秒后自动按 WPM 继续”
- 设备端识别可用性状态

### 6.2 播放页

顶部状态区显示：

- 固定模式：`固定 125 WPM · 横屏`
- 语音模式：`语音跟随 · 识别中`
- 回退状态：`语音暂不可用 · 固定 125 WPM`

实时模式下保留当前句高亮和字母级颜色高亮，并增加低干扰的识别状态提示。识别状态不能覆盖正文。

### 6.3 悬浮窗

沿用现有悬浮窗布局，增加：

- 当前模式和识别状态文字。
- “恢复跟随”操作。
- 回退模式下的 `慢5 / 快5`。

悬浮窗不得因为语音状态变化自动改变用户拖拽位置，除非用户点击“恢复跟随”。

## 7. 技术方案

### 7.1 模块划分

建议新增以下独立模块：

- `domain/voice/VoiceFollowMode.kt`：提词模式、识别状态和回退状态。
- `domain/voice/ScriptTokenMatcher.kt`：文本归一化、token 匹配、句子提交。
- `domain/voice/VoiceFollowEngine.kt`：接收识别结果，输出句子索引、字符进度和状态。
- `platform/voice/AndroidSpeechRecognizer.kt`：封装 Android 语音识别 API、权限和设备能力检查。

现有模块继续复用：

- `SpeechTextParser`：句子解析。
- `PlaybackEngine`：固定 WPM 速度、进度和预计剩余时间。
- `LocalStore`：保存用户选择的提词模式和回退 WPM。
- `PlaybackScreen`、`OverlayService`：分别接入相同的语音跟随输出。

### 7.2 数据流

```text
麦克风音频
   ↓
AndroidSpeechRecognizer
   ↓ partial/final 文本 + 状态
ScriptTokenMatcher
   ↓ 已确认句索引 + 当前句匹配进度
VoiceFollowEngine
   ├─ VOICE_LISTENING：按识别位置显示
   └─ FALLBACK_WPM：调用现有 PlaybackEngine
   ↓
PlaybackScreen / OverlayService
```

### 7.3 权限与前台服务

- Manifest 增加 `RECORD_AUDIO`。
- 主播放页在用户选择实时模式后申请运行时麦克风权限。
- 悬浮窗实时模式需要前台服务继续持有麦克风；目标 Android 版本下按系统要求声明 microphone foreground service 类型。
- 权限被拒绝时不反复弹窗，提供一次明确的“改用固定 WPM”操作。
- 识别停止或退出播放后立即释放识别器和音频资源。

## 8. 异常处理

| 情况 | 行为 |
|---|---|
| 用户拒绝麦克风权限 | 提示原因，提供固定 WPM 继续入口 |
| 无设备端英语识别 | 提示设备不支持离线语音跟随，回到固定 WPM |
| 识别结果为空约 2 秒 | 自动进入 FALLBACK_WPM |
| 识别服务临时错误 | 保持当前句，进入固定 WPM，提供重试 |
| 识别文本与台本不匹配 | 不跳句，继续当前句或回退 WPM |
| 用户环境噪声大 | 显示回退状态，不保存音频 |
| 用户手动拖动全文 | 暂停自动拉回，显示“恢复跟随” |
| 台本为空 | 禁止开始实时跟随，并提示先输入英文内容 |

## 9. 数据与隐私

- 不保存音频文件。
- 不上传演讲内容。
- 语音识别结果只保留当前匹配所需的短文本窗口，播放退出后清除。
- 固定 WPM 模式不申请麦克风权限。
- 设置中明确显示“音频不保存、不上传”。

## 10. 测试与验收计划

### 10.1 单元测试

- 英文大小写、标点、弯引号、连字符和缩写归一化。
- 当前句连续匹配时，字符进度单调递增。
- 少量错词不导致跨句跳跃。
- 单次识别结果最多推进一个句子。
- 2 秒无结果进入回退状态。
- 识别恢复后需要连续稳定结果才能接管。
- 固定 WPM 模式不调用语音识别适配器。

### 10.2 手动测试

- 安静环境正常英语朗读。
- 朗读中主动停顿 2～4 秒，确认回退后继续推进。
- 朗读速度突然加快和放慢。
- 重复一个词、改口、跳过一个词。
- 有背景噪声或距离麦克风较远。
- 拒绝权限、关闭系统语音识别、设备端识别不可用。
- 竖屏、横屏、悬浮窗、拖动全文和恢复跟随。
- 固定 WPM 模式全流程回归。

### 10.3 设备验收

至少验证：

- 一台支持设备端英语识别的 Android 设备。
- 一台不支持设备端识别或关闭识别服务的 Android 设备。
- Android 13/14 及以上的麦克风权限和前台服务行为。
- 低配置设备连续播放 5 分钟无明显内存增长或识别线程泄漏。

## 11. 分阶段执行计划

### Phase 1：模式和匹配核心

- 增加固定 WPM/实时跟随模式模型。
- 编写可注入识别结果的 token 匹配器。
- 完成句子级推进、候选结果和状态机单元测试。

### Phase 2：Android 设备端语音识别

- 封装识别器和设备能力检测。
- 增加运行时麦克风权限流程。
- 实现识别错误、无结果超时和固定 WPM 回退。

### Phase 3：主播放页接入

- 接入实时模式选择。
- 接入识别状态、当前句和字符进度。
- 保留固定 WPM 的所有现有逻辑和手动操作。

### Phase 4：悬浮窗接入

- 在前台服务中接入语音识别生命周期。
- 同步主播放页的匹配和回退状态。
- 验证悬浮窗拖拽、全文滚动和恢复跟随互不冲突。

### Phase 5：回归与发布

- 运行全部领域测试和识别匹配测试。
- 构建 Debug APK。
- 完成至少一台真机的实时朗读测试。
- 记录不支持设备端识别时的降级行为。

## 12. 非目标

- 不做逐字 100% 精准的专业字幕系统。
- 不做发音评分、语法纠错、翻译或 AI 改稿。
- 不保存或上传完整演讲音频。
- 不强制依赖网络识别服务。
- 不改变固定 WPM 模式的现有交互和视觉布局。

## 13. 待确认事项

- Android 设备端英语识别能力需要在目标手机上实测；不可用时按固定 WPM 降级。
- 第一个版本建议只实现句子级跟随，逐词跟随作为后续增强功能。
